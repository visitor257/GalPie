This document is divided into 2 parts:
1. Explanation of Story JSON Rules
2. Example JSON Parsing

Note:
1. Unless otherwise specified, all file paths should be relative paths starting from the location of the JSON file.

This document is based on the actual content of the current story/sample_create.json and the code implementation, and replaces the old version of the rules.
Fields that are not implemented (such as edit_storylineID_value / check_storyline inside scenes) have been removed from the rules or marked as "reserved".



1. Explanation of Story JSON Rules:
Top-level keys: "settings", "ui", "menu", "story_and_position"

"settings": dictionary (optional; defaults are used when missing)
    Description: Used to configure language support, window size, title, etc. When missing or empty, the program uses defaults (language falls back to "zh", window 1280x720, title "GalPie").
    Keys inside "settings": "language", "window_size", "window_title", "identify_code", "transition_color", "default_audio_lang_id", "extra_content", "use_main"

    "language": dictionary (optional; defaults to "zh" when missing)
        Description: Sets the supported languages. The current format is a dictionary: {language tag: language display name}.
        The program takes the first language tag in the dictionary as the initial language. When missing or empty, the program uses "zh" as the current language.
        Explanation of keys inside "language": language tags, e.g., "zh", "en", "ja", "ru"
        Example: {"zh": "中文", "en": "English", "ja": "日本語", "ru": "Русский"}
        Legacy format is also supported: a list such as ["zh", "en", "ru"], the program takes the first element as the initial language.

    "window_size": string or list (optional)
        Description: Sets the window size. It can be a single resolution string (legacy format), or a list of resolution strings (new format; index=0 is the initial resolution).
        String format is "<width>x<height>", e.g., "1280x720".
        List format, e.g., ["1280x720", "1600x900", "1920x1080"]; the options in the list will appear in the resolution dropdown of the settings panel.
        If not provided, it defaults to "1280x720".

    "window_title": string (optional)
        Explanation of "window_title": Sets the title of the game window. If not provided, it defaults to "GalPie".

    "identify_code": string (optional)
        Explanation of "identify_code": Sets an identification code for this story, used to manage story save files more conveniently.

    "transition_color": list (optional; default [0, 0, 0] black)
        Explanation of "transition_color": Sets the color displayed in the window during transitions, RGB format, three integers from 0 to 255, e.g., [0, 0, 0].
        The program uses this color as the transition color block in the following transition scenarios:
        - After clicking "Start Game": the main menu fades out, first fading into this color, staying for about 1.5 seconds, then fading into the story.
        - After confirming a load from the main menu: likewise first fades into this color, then fades into the loaded scene.
        - When the scene is blank/cleared (no elements at all), the window background is also this color.

    "default_audio_lang_id": string (optional)
        Explanation of "default_audio_lang_id": The fallback language tag for audio. When the audio file for the current language is missing in a scene's audio config, the program falls back to the audio file of this language tag (only effective for audio with json_mode=judge; see the scene-level "audio" explanation below). When missing, there is no fallback (if the current language has no file, nothing is played).

    "extra_content": dictionary (optional)
        Explanation of "extra_content": Registers additional-content (DLC) packages in the form {package_id: json_path}, e.g., {"ex_girl": "./ex/ex_girl.json"}.
        Each "package" is a standalone story JSON. After entering a package, every resource path inside it is resolved relative to that JSON's own directory (not the main work's directory).
        Packages are entered through the "ex_content" route of a scene/option "next" (see the "next" explanation below); the reserved id ":main:" refers to the main work.
        A package that cannot be read counts as not installed: the route moves on to the next candidate instead of failing.

    "use_main": bool (optional; default false; only used by additional-content packages)
        Explanation of "use_main": Whether this package may inherit resource definitions from the main work.
        true: inheritance allowed - character_and_motion / backgrounds / bgm / audio etc. that this package does not define are supplemented from the main work (objects with the same id are deep-merged field by field; fields written in this package win).
        false or missing: only this package's own definitions are used.
        Note: "story" (storylines) is never inherited - only this package's own storylines are played, otherwise same-named lines would be merged page by page and mix content.
        Paths are resolved separately: inherited main-work resources still resolve against the main work's directory; new paths written in this package resolve against this package's directory.

"ui": dictionary (optional; the default UI is used when missing)
    Description: Used to configure the interactive interface, such as the dialogue box and bottom menu. When missing, the default UI settings are used (default dialogue box style / name region / words region).
    Keys inside "ui": "confirm_ui", "chatbox_and_words_position", "bottom_menu"
    Additional-content package form: write the string "use_main" on any ui sub-item to keep the main work's setting for that item, e.g., "ui": {"chatbox_and_words_position": "use_main"}; the merge then does not override the main work's part.

    "confirm_ui": dictionary (optional; the default confirm dialog appearance is used when missing)
        Description: Interface configuration of the confirm dialog. The confirm dialog is used for operations that need a second confirmation: the main menu "Continue" (menu_pos.qload) before loading the latest save, the bottom menu "Q.Load" (quick load) before loading the latest save, the main menu "Quit" (menu_pos.quit) before exiting the game, and the bottom menu "Skip" before jumping to the next choice.
        The confirm dialog consists of a full-screen mask (color from settings.transition_color, 50% opacity) plus a centered rounded box with one line of question text and two buttons (Cancel/Confirm).
        Keys inside "confirm_ui": "ui_mode", "color", "text_color", "cancel_color", "confirm_color"

        "ui_mode": string (optional)
            Explanation of "ui_mode": The interface mode. Currently only "default" (preset style) is supported.

        "color": list (optional; default [255, 255, 255, 217])
            Explanation of "color": The background color of the confirm box, RGBA format.

        "text_color": list (optional; default [30, 30, 30])
            Explanation of "text_color": The color of the question text (e.g. "Confirm?"), RGB format.

        "cancel_color": list (optional; default [255, 255, 255])
            Explanation of "cancel_color": The background color of the "Cancel" button, RGB format. The text color is chosen automatically by brightness (same rule as bottom menu button_color).

        "confirm_color": list (optional; default [30, 30, 30])
            Explanation of "confirm_color": The background color of the "Confirm" button, RGB format. The text color is chosen automatically by brightness.

    "chatbox_and_words_position": dictionary (optional; the default dialogue box style and regions are used when missing)
        Description: Settings of the dialogue box style. When missing, the default dialogue box style / name region [[76,60],[270,149]] / words region [[310,60],[805,149]] are used.
        All five keys inside it are optional, each using its default value when missing.
        Keys inside "chatbox_and_words_position": "chatbox", "text_color", "readed_text_color", "name_show_region", "words_show_region"

        "chatbox": string (optional; the default dialogue box style is used when missing)
            Explanation of "chatbox": The storage location of the dialogue box style (should be an image). The path should be relative to the location of the JSON file, e.g., "./res/ui/chatbox.png"

        "text_color": list (optional; default [255, 255, 255] white)
            Explanation of "text_color": The color of unread text (lines played for the first time), RGB format, three integers from 0 to 255, e.g., [255, 255, 255].

        "readed_text_color": list (optional; default [255, 255, 255] white)
            Explanation of "readed_text_color": The color of read text (lines of scenes that have already been played), RGB format, three integers from 0 to 255, e.g., [255, 255, 0].
            The program determines whether the current scene has been read from the read history (.gpreaded): lines of read scenes use this color, lines of unread scenes use "text_color" above.

        "name_show_region": list (optional; the default region [[76,60],[270,149]] is used when missing)
            Explanation of elements inside "name_show_region": The list should contain two lists, representing respectively the top-left and bottom-right coordinates of the region where the speaker's name is displayed inside the dialogue box. The coordinate system is based on the image of the dialogue box style "chatbox". The top-left corner of the image is the origin (0 point); the x axis increases to the right and the y axis increases downward. Format example: [[76,60],[270,149]], meaning the pixel at (76, 60) on the dialogue box style (image) is the top-left and the pixel at (270, 149) is the bottom-right of the region where the speaker's name is displayed.

        "words_show_region": list (optional; the default region [[310,60],[805,149]] is used when missing)
            Explanation of elements inside "words_show_region": Similar to "name_show_region"; the list should contain two lists, representing respectively the top-left and bottom-right coordinates of the region where the subtitle text is displayed inside the dialogue box. The coordinate system is based on the image of the dialogue box style "chatbox". The top-left corner of the image is the origin (0 point); the x axis increases to the right and the y axis increases downward. Format example: [[310,60],[805,149]], meaning the pixel at (310, 60) on the dialogue box style (image) is the top-left and the pixel at (805, 149) is the bottom-right of the region where the subtitle is displayed.

    "bottom_menu": dictionary (optional)
        Description: Sets the bottom menu bar during the story. If not provided, no bottom menu bar is shown.
        Keys inside "bottom_menu": "mode", "color", "button_color", "backlog_bgcolor", "save", "height_ratio", "extend"

        "mode": string (optional)
            Explanation of "mode": The mode of the bottom menu; currently only "default" (preset style) is supported.
            default mode: Shows a semi-transparent menu bar at the bottom of the window, with the "⊙" button, the "Log" button, the "Settings" button, the "Skip-to-choice" button, the "Skip (▷▷)" toggle, the "Auto-play (▷)" toggle, the "Load" button, the "Save" button, the "Quick Load (Q.Load)" button, and the "Quick Save (Q.Save)" button arranged from right to left.
            The "⊙" button is a hide toggle: pressing it hides the dialogue box and the whole bottom menu (including the menu bar itself) while the story keeps advancing; pressing anywhere (left or right click) restores them. The dialogue box is restored to its visibility before hiding (if it was already hidden by the story, e.g. on a transition page, it stays hidden).
            The Settings button opens the settings panel; the Log button opens the backlog panel; the Save button opens the save panel; the Load button opens the load panel (same as main menu "Load"); the Quick Save button saves directly to the quick save slot; the Quick Load (Q.Load) button shows a confirm dialog (appearance from ui.confirm_ui), then loads the latest save.
            While any of the settings/log/save/load panels is open, pressing the right mouse button is equivalent to pressing that panel's "Back" button, closing it directly.
            (A=auto-play, S=skip)
            Skip and Auto-play are mutually exclusive — enabling one automatically disables the other; opening the settings/log/save panel pauses both, and they resume after returning to the story.

        "color": list (optional)
            Explanation of "color": The fill color of the bottom menu bar, RGBA format, four integers from 0 to 255, e.g., [0, 0, 0, 200].
            Default value is [0, 0, 0, 255].

        "height_ratio": float (optional; default 0.03)
            Explanation of "height_ratio": The menu bar height as a ratio of the logical frame height, e.g., 0.03 = 21.6 px out of 720 (rounded).

        "extend": integer (optional; default 50)
            Explanation of "extend": Extra pixels the menu bar extends below the logical bottom, preventing exposed edges / seams when the window aspect ratio deviates from 16:9; write 0 to disable. The extension is clipped with the scene and does not affect fitInView scaling.

        "button_color": list (optional)
            Explanation of "button_color": The background color of the buttons on the bottom menu bar (Log/Settings/Skip/Auto-play/Save/Quick Save), RGBA format, e.g., [0, 0, 0, 200].
            Default value is [0, 0, 0, 255]. The button text color is chosen automatically based on the brightness of this color:
            - Sum of the three RGB values < 383: white text in normal state; on hover the button turns white with black text.
            - Sum of the three RGB values >= 383: black text in normal state; on hover the button turns black with white text.

        "backlog_bgcolor": list (optional)
            Explanation of "backlog_bgcolor": The background color of the backlog (log) panel, RGBA format, e.g., [255, 255, 255, 200].
            Default value is [255, 255, 255, 200].

        "save": dictionary (optional)
            Description: The interface configuration of the save panel / load panel. The save panel and the load panel share this structure (the load button on the main menu has its own config; see "menu_pos.load" below).
            Keys inside "save": "ui_mode", "color", "saves_color", "saves_text_color", "text_color", "button_color"

            "ui_mode": string (optional)
                Explanation of "ui_mode": The interface mode; currently only "default" (preset style) is supported.

            "color": list (optional; default [255, 255, 255, 217])
                Explanation of "color": The background color of the panel, RGBA format.

            "saves_color": list (optional; default [185, 122, 87, 255])
                Explanation of "saves_color": The background color of the save slots, RGBA format. On hover it automatically becomes lighter/darker while keeping the original hue: when the sum of the three RGB values < 383, it blends 35% toward white; when >= 383, it blends 35% toward black.

            "saves_text_color": list (optional; default [255, 255, 255])
                Explanation of "saves_text_color": The color of the text inside the save slots (line/date-time/trash icon/empty-slot "SAVE" text/confirmation text), RGB format.
                Note: the text of the confirm/cancel buttons is always white and is not affected by this config.

            "text_color": list (optional; default [30, 30, 30])
                Explanation of "text_color": The color of the static text inside the panel (the "Save Game"/"Load Game" title at the top-left, the page number at the bottom, etc.), RGB format.

            "button_color": list (optional; default [0, 0, 0, 255])
                Explanation of "button_color": The background color of the buttons on the bottom toolbar of the panel (◀ page prev ▶, + add page, Main Menu, Back), RGBA format. The text/hover rules are the same as the bottom menu bar's button_color (brightness < 383 white text/hover turns white with black text; >= 383 black text/hover turns black with white text).

"menu": dictionary (optional)
    Description: Sets the main menu (start screen). If not provided, the story starts directly on launch (playing from the first page of the current storyline) without showing a main menu.
    If provided, the main menu is shown first on launch, and the story starts only after clicking the "start" button.
    Keys inside "menu": "bg", "bgm", "change", "title", "button", "button_touched", "text_rgb", "menu_pos"

    "bg": string (optional)
        Explanation of "bg": The path of the main menu background image (relative to the JSON file), e.g., "./res/menu/bg.png".

    "bgm": dictionary (optional)
        Description: The background music of the main menu. It plays when entering the main menu and stops when leaving it.
        Keys inside "bgm": "bgm", "in", "out"

        "bgm": string (required; as long as menu.bgm is written, it must be present)
            Explanation of "bgm": The path of the main menu background music file (relative to the JSON file), e.g., "./res/audio/bgm_menu.mp3".

        "in": string (optional; defaults to playing directly)
            Explanation of "in": The fade-in effect when the music starts playing. Supports "normal" (play directly) and "gradient" (fade in).

        "out": string (optional; defaults to stopping directly)
            Explanation of "out": The fade-out effect when the music stops (leaving the main menu). Supports "normal" (stop directly) and "gradient" (fade out).

    "change": list (optional)
        Explanation of "change": The transition effect when the main menu appears. Format is [[r,g,b], "gradient"],
        i.e., a list consisting of a color and an effect name. The program takes the 2nd element (the effect name) as the transition effect.
        The 1st element (the color) is used as the backdrop block during the fade-in: when the game starts (or when the ending returns to the main menu) a full-screen block of that color is laid down before the menu fades in; when coming back from the settings/save panels no block is laid down (the menu just fades in). When omitted, no block is drawn and the viewport's black background shows through.
        Currently supported effects: gradient "gradient".

    "title": dictionary (optional)
        Explanation of "title": The main menu title image, given by language tag with the image path.
        The program first takes the image for the current language; if absent, it falls back to the "zh" image; if still absent, it takes the first one.
        Example: {"zh": "./res/menu/title.png"}.

    "button": string (required)
        Explanation of "button": The path of the normal style image of the main menu button, e.g., "./res/menu/button.png".
        Note: The code directly indexes menu["button"]; if missing, an error is raised. Therefore, as long as "menu" is provided, "button" must also be provided.

    "button_touched": string (optional)
        Explanation of "button_touched": The path of the style image of the main menu button when hovered/pressed by the mouse, e.g., "./res/menu/button_touched.png".

    "text_rgb": list (optional)
        Explanation of "text_rgb": The color of the main menu button text, RGB format, three integers from 0 to 255, e.g., [255, 255, 255].
        Default value is [255, 255, 255].

    "menu_pos": dictionary (optional)
        Description: Sets the positions and texts of the title and buttons in the main menu.
        Explanation of keys inside "menu_pos": It can contain "title" and any button tags (such as "qload", "start", "load", "settings", "quit").

        "title": list (optional)
            Explanation of elements inside "title": The position coordinate [x, y] of the title image on the main menu background.
            The coordinate system is based on the main menu background image. The top-left corner of the image is the origin (0 point); the x axis increases to the right and the y axis increases downward.
            Example: [54, 48].

        <button tag>: list (required, e.g., "qload"/"start"/"load"/"settings"/"quit")
            Description: Sets a main menu button. The list structure is: [position, text dictionary, additional config (optional)]
            1st element: The position coordinate [x, y] of the button image on the main menu background.
            2nd element: The text dictionary, giving the button text by language tag, e.g., {"zh": "开始游戏", "en": "Start Game", "ja": "ゲーム開始", "ru": "Начать игру"}.
                The program takes the text for the current language; if absent, it takes the first text in the dictionary.
            3rd element (optional): The additional config dictionary, e.g., {"ui_mode": "default"}.
            Currently built-in supported button tags and their functions:
                "qload": Continue game (quick load). On click, if any save exists, a confirm dialog is shown (appearance from ui.confirm_ui); on confirm it loads the latest save (quick save first) and enters the story. If no save exists, clicking does nothing (no dialog).
                "start": Start the game; clicking enters the story.
                "load": Opens the load panel (load game interface). Its additional config dictionary has the same structure as the "save" config of the bottom menu bar (color/saves_color/saves_text_color/text_color/button_color), used to set the appearance of the load panel; defaults are used if not provided.
                "settings": Opens the settings panel (language/resolution switching, etc.). Its additional config dictionary (ui_mode/color/text_color/button_color) is used to set the appearance of the settings panel; defaults are used if not provided.
                    That dictionary is actually an override table for the preset panel style. Besides the four above you can also write: margin_ratio (inset ratio on all four sides, default 0.1), corner_radius (default 24), fill_color/fill_alpha (panel fill and opacity, default [255,255,255] / 217), fade_duration (fade-in ms, default 500), button_radius/button_height/button_margin/button_bottom_margin/button_gap (bottom buttons), title_top_margin/title_left_ratio/title_size/title_stroke_width (title), item_left_margin/item_gap/column_gap (setting rows), res_label_size/res_value_size/res_arrow_size (font sizes), button_opacity, z (layer); anything omitted keeps its default.
                    Deprecated (still accepted by the code but no visible effect): border_offset, border_width, border_color, border_alpha (the old white rim was removed).
                "quit": Quit the game. On click a confirm dialog is shown (appearance from ui.confirm_ui, question text "Quit?"); the game quits only after confirmation.
            Other custom button tags are currently not bound to any function (clicking does nothing); they are displayed only.

"story_and_position": dictionary (required)
    Description: Sets the story content, characters, backgrounds, etc.
    Keys inside "story_and_position": "character_and_motion", "backgrounds", "bgm", "selection_button", "storyline_settings", "story"

    "character_and_motion": dictionary (optional; referencing a character in a scene prints "character not defined" when missing)
        Description: Sets the characters that have sprites
        Explanation of keys inside "character_and_motion": Custom character tags, e.g., "girl", "congyu", "丛雨"

        <character tag>: dictionary (required)
            Keys inside a character tag: "name", "form", "face"

            "name": dictionary (required)
                Description: Sets the title/address of this character tag in the game
                Explanation of keys inside "name": The language tags defined in "language" of "settings", e.g., if {"zh": "中文", "en": "English"} is set in "language", this dictionary should be: {"zh": "丛雨", "en": "Murasame"}

                <language tag>: string (required)
                    Content explanation: Sets the title/address of this character tag in different languages in the game

            "form": dictionary (required)
                Description: Sets the different forms of this character, and sets the image file path each form points to
                Explanation of keys inside "form": Custom form tags, e.g., "校服", "工作", "校服2"

                <form tag>: string (required)
                    Content explanation: The image file path the form points to, e.g., "校服": "./res/character/girl/uniform.png"

            "face": dictionary (optional)
                Description: Sets the facial expressions of this character, and sets the image file path each expression points to. You may also include the expression directly in the form image and call that form directly in the story later, thus omitting this part.
                Explanation of keys inside "face": Custom expression tags, e.g., "微笑", "脸红", "平常"

                <expression tag>: string (required)
                    Content explanation: The image file path the expression points to, e.g., "脸红": "./res/character/girl/shy.png"

    "backgrounds": dictionary (optional; referencing a background in a scene prints "background not defined" when missing)
        Description: Sets the tags of different backgrounds, and sets the image file path each background points to
        Explanation of keys inside "backgrounds": Custom background tags, e.g., "学校", "教室", "公园"

        <background tag>: string (required)
            Content explanation: The image file path the background points to, e.g., "公园": "./res/bg/park.png"

    "bgm": dictionary (optional)
        Description: Sets the definition table of the story BGM. Scene-level bgm operations (see "bgm" inside a scene below) reference the paths here by id.
        Explanation of keys inside "bgm": Custom BGM tags

        <BGM tag>: string (required)
            Content explanation: The audio file path the BGM points to, e.g., "bgm1": "./res/audio/bgm_1.mp3"

    "selection_button": dictionary (optional)
        Description: Sets the appearance of the option buttons in selection scenes. The default button style is used when missing.
        Keys inside "selection_button": "text_color", "normal", "touched"

        "text_color": list (optional; default [255, 255, 255] white)
            Explanation of "text_color": The color of the option button text, RGB format.

        "normal": string (optional)
            Explanation of "normal": The path of the option button image in the normal state (not hovered), relative to the JSON file, e.g., "./res/ui/selection.png".

        "touched": string (optional)
            Explanation of "touched": The path of the option button image in the hovered state, relative to the JSON file, e.g., "./res/ui/selection_touched.png".

    "storyline_settings": dictionary (optional; the main storyline defaults to "main" when missing)
        Description: Sets the storyline configuration: the starting main storyline, the route-selection threshold, and the initial scores of the branches.
        Keys inside "storyline_settings": "main_storyline", "score_gap", "storyline_id_score"

        "main_storyline": string (optional; default "main")
            Explanation of "main_storyline": The tag of the main storyline (the storyline played first when the game starts), e.g., "main".

        "score_gap": float (optional; default 0)
            Explanation of "score_gap": The route-selection threshold. In judge routing, if the score difference between the first and the second place >= score_gap, the first-place storyline is entered; otherwise the fallback storyline is entered (see the "next" judge format inside a scene below).

        "storyline_id_score": dictionary (optional)
            Description: The initial scores of the branch storylines (for scoring). The "score" of an option is added to the score of the corresponding storyline.
            Explanation of keys inside "storyline_id_score": storyline tags

            <storyline tag>: float (required)
                Content explanation: The initial score of that storyline, e.g., "main": 1.0

    "story": dictionary (optional, but a storyline tag must correspond to a key here, otherwise that storyline has no content)
        Description: The story content of each storyline. If missing, or a storyline tag has no corresponding content, "story over" is printed when playing.
        Explanation of keys inside "story": storyline tags (e.g., "main", "cafe_girl", "girl", "end").
        The starting main storyline is specified by "main_storyline" in "storyline_settings" above; the other storylines are entered via the "next" of an option / the "next" of a scene ("end" is the ending storyline).

        <storyline tag>: dictionary (required)
            Description: Story and plot content, as well as the settings of scenes and subtitles. Note that with "clear_all": false, the scene settings of the previous page continue to exist if not set again; if some part is set again, that part is replaced with the new settings (where "bg" is replaced as a whole, and "characters" is replaced tag by tag: the character tags that are set again are replaced with the new settings, while other characters that are not set are kept). You can learn more in the example JSON parsing in Part 2.
            Explanation of keys inside the dictionary: page number, starting from 1

            <page number>: list (required)
                Description: Sets the scenes of this page
                Explanation of elements inside the list: The elements are dictionaries; if the list has n elements (dictionaries), it means there are n scenes (n cannot be less than 1)

                Element inside the list: dictionary (required)
                    Description: The settings of a scene
                    Keys inside the dictionary: "clear_all", "change", "stay_time", "bg", "characters", "chatbox", "content", "bgm", "audio", "selection", "next"

                    "clear_all": bool (optional, default false; but the "clear_all" of the first page of every storyline must be true)
                        Description: Whether to clear the content of the previous page's scenes. true means yes, false means no. The "clear_all" of the first page of every storyline must be true, otherwise the content of the previous storyline/page will remain.

                    "change": string or list (optional)
                        Explanation of "change": Sets the transition effect; by default it changes directly
                        Currently supported effects:
                            Gradient  "gradient"
                            Slide     "slide"
                        Gradient form:
                            String: Fill in the effect name directly, e.g., "change": "gradient".
                            List: two elements, the first is the effect name and the second is the effect duration in seconds (float), e.g., "change": ["gradient", 0.2] (gradient 0.2 s), "change": ["gradient", 2] (gradient 2 s).
                            Dictionary: write the second element as {"time": seconds, "start_change": {"last": seconds, "this": seconds}}; compared with the list form it adds a delayed start so the old and new frames can be staggered, e.g.,
                                "change": ["gradient", {"time": 0.5, "start_change": {"last": 0.1, "this": 0}}]
                                -> the old frame starts fading out after 0.1 s and finishes at 0.6 s; the new frame starts fading in immediately and finishes at 0.5 s.
                                "time": the fade-out/fade-in duration for each side (seconds; default 1.0).
                                "start_change.last": how many seconds the old frame (fade-out side) waits before starting (default 0).
                                "start_change.this": how many seconds the new frame (fade-in side) waits before starting (default 0).
                                This dictionary form works for the scene-level change, chatbox.change, and gradient replacement of characters/backgrounds.
                        Slide form: ["slide", axis, old side, new side(, options)]
                            Axis: "horizontal" (slides left/right, the divider is vertical) / "vertical" (slides up/down, the divider is horizontal); default "horizontal".
                            Old side / new side: "left"/"right" (horizontal axis) or "top"/"bottom" (vertical axis); default right->left for the horizontal axis and bottom->top for the vertical axis.
                            Options: the 5th element (optional), either a number or a dictionary.
                                Number: the transition duration in seconds, equivalent to {"time": seconds}.
                                Dictionary keys: "time", "slide_element"
                                "time": The transition duration in seconds (float); default 1.0, minimum 0.05 (smaller values are raised to 0.05).
                                "slide_element": list (optional) defining the appearance elements drawn along the moving divider (edging, shadow, color bands, ...). The list moves together with the divider.
                                    Each element is a dictionary with keys: "area", "color"
                                    "area": [[x1,y1],[x2,y2]], two diagonal points forming a rectangle. The coordinate system uses "the origin on the divider" as (0,0):
                                        Horizontal axis (vertical divider): the origin is the topmost point of the divider; x is unbounded (write the offset relative to the divider, positive or negative); y is bounded (frame height) and negative values count from the tail.
                                        Vertical axis (horizontal divider): the origin is the leftmost point of the divider; y is unbounded (write the offset relative to the divider); x is bounded (frame width) and negative values count from the tail.
                                        Negative tail rule: -1 is the last finite value on that axis (for horizontal, the frame height such as 720; for vertical, the frame width such as 1280), -2 is the second-to-last (719 / 1279), and so on. This cannot be used on the unbounded axis.
                                    "color": [r,g,b] or [r,g,b,a], fills that area with the color (a defaults to 255).
                                    Layer order: later elements in the list are painted on top of earlier ones.
                            Example: "change": ["slide", "horizontal", "right", "left"] (default 1 s)
                                     "change": ["slide", "horizontal", "right", "left", {"time": 0.5}] (finishes in 0.5 s)
                                     "change": ["slide", "horizontal", "right", "left", {"time": 0.5, "slide_element": [{"area": [[-5,0],[5,-1]], "color": [0,0,0,170]}]}]
                                        (a 10px-wide, full-height, semi-transparent black edge straddling the vertical line; -1 means the frame height)

                    "stay_time": float or int (optional)
                        Explanation of "stay_time": How long this scene stays, in seconds (e.g., "stay_time": 1). Its effect is exactly the same as the "animate" duration of the empty-string "" character tag: the engine waits this long before automatically moving on to the next scene, and a click skips the wait.
                        Typical use: transition pages that have no text and no audio and only show a transition/fade (e.g., the pause before the black screen at the ending), so you no longer need to write an empty-character animation just to control the pacing.
                        Two notes: (1) if the scene has a valid "audio", this field has no effect (the voice itself sets the pace); (2) if the empty-string "" character's "animate" duration is also present, the larger of the two is used.

                    "bg": string or dictionary (optional)
                        Explanation of "bg": Sets the background; there are three ways to write it.
                        String form: the content should be a background tag set in "backgrounds" above, e.g., "bg": "公园".
                        Solid-color form: {"color": [r,g,b]} a solid-color background, i.e., the whole screen is filled with an RGB color as the background, e.g., "bg": {"color": [0, 0, 0]} (black background).
                        Framing form (new syntax): {"bg": background tag, "zoom": float, "start_pos": [x, y], "animate": [...]}
                            Keys inside the dictionary: "bg", "zoom", "start_pos", "animate"
                            "bg": the background tag (required; taken from "backgrounds" above).
                            "zoom": zoom factor (optional; default 1.0). The original image is first scaled to fill the logical canvas (KeepAspectRatioByExpanding), then multiplied by this factor.
                            "start_pos": the coordinate [x, y] of the top-left corner of the display region on the *zoomed* image (pixels; optional; centered when omitted).
                                Example: a 720p image with zoom 1.5 becomes 1920x1080, so start_pos x ranges 0-640 and y ranges 0-360.
                            "animate": animation group list (optional), same structure as character animations ([[{...}], ...]); keys inside each group: "time", "move", "zoom".
                                "move": relative displacement (added on top of the starting framing position), e.g., [[640,0]] moves the background 640 pixels to the right.
                                "zoom": absolute target factor (interpolated from the current zoom; background zoom can be animated).
                            With this form the coordinates are logical-canvas coordinates and characters no longer follow the background offset (the old centered offset no longer applies).

                    "characters": dictionary (optional)
                        Description: Sets the characters with sprites to appear on stage
                        Explanation of keys inside "characters": The character tags set in "character_and_motion" above; the empty string "" can also be used as a key (see below)

                        <character tag>: dictionary (required)
                            Description: Sets the form, position, expression, zoom, animation, etc. of the character appearing on stage
                            Keys inside the dictionary: "form", "pos", "face", "zoom", "animate"

                            "form": string (required)
                                Explanation of "form": The form tag set in "form" of this character tag in "character_and_motion" above

                            "pos": list (required)
                                Explanation of elements inside "pos": The list should contain two values, corresponding to the x and y coordinates of the form image on the background image. The coordinate system is based on the background image. The top-left corner of the image is the origin (0 point); the x axis increases to the right and the y axis increases downward. Format example: [320,80], meaning the form image is placed at the pixel (320, 80) on the background image.

                            "face": list or string (required)
                                Explanation of "face": There are two ways to write it.
                                List form: It has two elements. The first is a string, the expression tag set in "face" of this character tag in "character_and_motion" above; the second is a list containing two values, corresponding to the x and y coordinates of the expression image on the form image. The coordinate system is based on the form image. The top-left corner of the image is the origin (0 point); the x axis increases to the right and the y axis increases downward. Format example: [0,0], meaning the expression image is placed at the pixel (0, 0) on the form image. The whole list format is: ["脸红",[0,0]].
                                Note: In the code, setup_character only takes the 1st element of the list (the expression tag); the 2nd element (the offset coordinate) is not used in the current version. The expression is always drawn at the top-left corner (0,0) of the form image; this coordinate field is reserved.
                                String form: Fill in the expression tag directly, e.g., "face": "平常".
                                Note: The code directly indexes char_info["face"]; if missing, an error is raised. Therefore, as long as "characters" is provided, "face" must also be provided.

                            "zoom": float (optional)
                                Explanation of the value of "zoom": Sets the zoom of the character, default 1.0. Less than (<) 1.0 shrinks, greater than (>) 1.0 enlarges.

                            "animate": list (optional)
                                Description: Sets the animation of the character in this scene
                                Explanation of elements inside the list: The elements are lists; each list is a group of animations. Animations within the same group play simultaneously, and groups play in sequence.

                                Element inside the list (a group of animations): list (required)
                                    Elements inside the group: dictionaries; a group can contain multiple animations, which play simultaneously.

                                    Keys inside the dictionary: "time", "zoom", "move"

                                    "time": float (optional; if missing or 0, that animation is skipped; it is recommended to fill it in)
                                        Explanation of the value of "time": The duration of the animation, in seconds. If missing or 0, the animation is not executed (skipped directly).

                                    "zoom": float (optional)
                                        Explanation of the value of "zoom": Sets the zoom animation. Within the animation duration ("time"), the character's zoom changes from the value of "zoom" above to this value. If it is not the first group, it zooms from the value at the end of the previous group to this value. You can learn more in the example JSON parsing in Part 2.

                                    "move": list (optional)
                                        Explanation of elements inside "move": The elements are lists with no specific upper limit on the number of elements; each list contains two numbers, corresponding to the x and y coordinates. The x axis increases to the right and the y axis increases downward. The coordinates are relative to the character itself. Within the animation duration ("time"), the character moves to the relative coordinates in order. Example: to move the character left 10, then down 10, then right 10, then up 10, fill in: [[-10,0],[0,10],[10,0],[0,-10]]

                        Empty-string "" character tag (key is ""): dictionary (optional)
                            Description: An image-less empty character — no image is loaded; only "animate" is used to compute the total animation duration as the stay/wait of this scene (visually the picture stays at its current state for the animation duration). It is used only in scenes without text that need a stay (such as a black-screen transition page).
                            Keys inside the dictionary: "animate" (optional, same format as above)

                    "chatbox": dictionary (optional)
                        Description: Controls the showing and hiding of the dialogue box (and the name/subtitle display regions)
                        Keys inside "chatbox": "visible", "change"

                        "visible": bool (required)
                            Explanation of the value of "visible": Whether to show the dialogue box. true shows it, false hides it.

                        "change": string or list (optional)
                            Explanation of "change": The transition effect of showing/hiding the dialogue box. Currently supported effects:
                                Gradient  "gradient"
                            String form: fill in the effect name directly, e.g., "change": "gradient" (default 1 second).
                            List form: two elements, the first is the effect name and the second is the duration in seconds (float), e.g., "change": ["gradient", 0.3] (fade out/in in 0.3 s), "change": ["gradient", 2] (2 s).
                            When hiding, the duration is the fade-out time; when showing, it is the fade-in time.

                    "content": dictionary (optional)
                        Description: Sets the dialogue content. Scenes without this field (such as pure background-switching pages) are directly marked as having text and audio finished, and automatically advance to the next scene / wait for page turning.
                        Keys inside "content": "speaking"/"speaking_name", "words"

                        "words": dictionary (required; as long as "content" is written, "words" must be present)
                            Description: Sets the dialogue subtitle for the language corresponding to each language tag. You can learn more in the example JSON parsing in Part 2.
                            Note: In the code, display_dialog directly indexes content["words"]; if missing, an error is raised. Therefore, as long as "content" is written, "words" must be provided.
                            The subtitle takes the text for the current language; if absent, it falls back to "zh"; if still absent, it takes the first non-empty value in the dictionary; an empty string only as the last resort.
                            Explanation of keys inside "words": The language tags set in "language" of "settings" above

                            <language tag>: string (required)
                                Content explanation: The subtitle of the dialogue in the language corresponding to this language tag

                        "speaking": dictionary / "speaking_name": string (both optional; both may be omitted; if both are omitted, the name is displayed as empty)
                            Description: Sets the speaker's name. If both are filled in, "speaking_name" takes priority.
                            Explanation of "speaking": Sets the speaker's name for the language corresponding to each language tag. You can learn more in the example JSON parsing in Part 2.
                            The name takes the text for the current language; if absent, it falls back to "zh"; if still absent, it takes the first non-empty value in the dictionary; an empty string only as the last resort.
                            Explanation of keys inside "speaking": The language tags set in "language" of "settings" above

                            <language tag>: string (optional)
                                Content explanation: The speaker's name in the language corresponding to this language tag (can be an empty string "", meaning no name)

                            Explanation of "speaking_name": If the speaker is set in "character_and_motion" above, the character tag set there can be used directly here
                            Content explanation of "speaking_name": The character tag set in "character_and_motion" above. The program takes the title for the current language from the "name" dictionary of that character; if absent, it falls back to "zh"; if still absent, an empty string.

                    "bgm": list (optional)
                        Description: Scene-level background music operations, executed in order. The id comes from the "bgm" definition table in "story_and_position" above (the empty string "" can also be used to stop the current BGM).
                        Explanation of elements inside the list: The elements are dictionaries; each dictionary is one BGM operation.
                        Keys inside the dictionary: "id", "in", "out", "delay"

                        "id": string (required)
                            Explanation of "id": The BGM tag (from the "bgm" definition table in "story_and_position"); the empty string "" stops the BGM currently playing.

                        "in": string or list (optional)
                            Explanation of "in": The entrance effect when starting to play. Supports "normal" (play directly) and "gradient" (fade in); a list ["gradient", seconds] can also be filled in to specify the fade-in duration.

                        "out": string or list (optional)
                            Explanation of "out": The exit effect when stopping. Supports "normal" (stop directly) and "gradient" (fade out); a list ["gradient", seconds] can also be filled in to specify the fade-out duration.

                        "delay": float (optional; default 0)
                            Explanation of the value of "delay": The delay in seconds before execution. When greater than 0, the operation is executed later at the scheduled time; page turning does not affect already-scheduled delayed operations.

                    "audio": dictionary (optional)
                        Description: Scene-level voice/sound-effect configuration. Playback: parallel within a group, sequential between groups; when all have finished, the audio is marked as finished (can be skipped by clicking).
                        Keys inside "audio": "json_mode", "play_in_order"

                        "json_mode": string (optional; default "normal")
                            Explanation of "json_mode": The parsing mode of the audio config. Supports:
                            - "normal": "play_in_order" is a multi-language dictionary; only the audio list of the current language is taken. If that language has no file, nothing is played.
                            - "judge"  : "play_in_order" is a template 2D list; <line>/<page>/<lang_id> in the file names are replaced with the current storyline/page/language. When the file of the current language is missing, it falls back to the language specified by "default_audio_lang_id" in "settings" above.

                        "play_in_order": dictionary or 2D list (required; as long as "audio" is written, it must be present)
                            Explanation of "play_in_order": The audio file list.
                            With json_mode=normal: a multi-language dictionary whose keys are language tags and values are 2D lists (sequential between groups, parallel within a group), e.g., {"zh": [["./res/audio/a_zh.wav"]], "en": [["./res/audio/a_en.wav"]]}.
                            With json_mode=judge: a template 2D list, e.g., [["./res/audio/audio_girl_<line>_<page>_<lang_id>.wav"]].

                    "selection": dictionary (optional)
                        Description: Sets a selection scene (option page). This scene only shows options and waits for the player to click before jumping.
                        Keys inside "selection": "change", "selection"

                        "change": string (optional; reserved)
                            Explanation of "change": Originally planned as the transition effect when the options appear; the program currently ignores this field (writing it has no effect). Kept for future versions.

                        "selection": list (required)
                            Description: The option list.
                            Explanation of elements inside the list: The elements are dictionaries; each dictionary is one option.
                            Keys inside the dictionary: "text", "score", "next"

                            "text": dictionary (required)
                                Explanation of "text": The option text (by language tag), e.g., {"zh": "是的，我经常来", "en": "Yes, I come here often"}.

                            "score": list (required)
                                Explanation of "score": Two elements; the first is a storyline tag and the second is a score value. After this option is selected, this score is added to the corresponding storyline (for scoring, affecting later judge routing), e.g., ["main", 0.5].

                            "next": dictionary (required)
                                Explanation of "next": The jump route after this option is selected; the format is the same as the scene-level "next" below (e.g., {"direct": ["main", "18"]}).

                    "next": string or dictionary (optional)
                        Description: The jump route after the scene finishes playing (where to jump after this page/scene ends). If not filled in, the next scene/next page plays in order.
                        Supported formats:
                        - String "end": The last page of the whole story; after it finishes, the game automatically returns to the main menu.
                        - Dictionary {"direct": [storyline, page]}: Directly jumps to the specified page of the specified storyline, e.g., {"direct": ["main", "41"]}.
                        - Dictionary {"judge": [[candidate storyline list], [fallback]]}: A scoring-based route-selection route. The candidate storyline list may contain multiple [storyline, page] entries; the fallback is a single fixed [storyline, page]. In the judgement, the current scores of the storylines (initial values from "storyline_id_score" in "storyline_settings"; the "score" of options is added) are compared and the first place is taken: if the score difference between the first and the second place >= "score_gap", the first-place storyline is entered; otherwise the fallback is entered. Example: {"judge": [[["girl", "1"]], [["main", "41"]]]}.
                        - Dictionary {"ex_content": [[package, storyline, page], ...]}: Cross-package (additional content) route.
                            "package": the package id of a story JSON, registered in settings.extra_content ({package_id: json_path}).
                            Two reserved forms: ":this:" = the package you are currently in; ":main:" = the main work (the JSON currently opened).
                            The colon form ":package id:" (id taken from the main work's settings.extra_content) explicitly tags a package id and is exactly equivalent to writing the bare id; the id itself may not contain colons. A form like ":a:b:" is treated as an invalid candidate (a message is printed, the candidate is skipped and the route moves on); an unregistered id simply counts as "cannot be read" and is skipped too.
                            Candidates are tried in list order: only when a package cannot be read, or that package has no such storyline/page, does the route move on to the next candidate; the first valid candidate is the target and is entered immediately.
                            With a single valid element the result is the same as entering it directly.
                            After entering the target package, its resource paths resolve relative to its own JSON directory.
                            Example: {"ex_content": [[":main:", "end", "1"]]} (after the additional content ends, return to page 1 of the main work's "end" storyline)
                                     {"ex_content": [["dlc_a", "main", "3"], [":main:", "main", "41"]]} (prefer dlc_a; fall back to the main work if unreadable)
                                     {"ex_content": [[":dlc_a:", "main", "3"]]} (writing ":dlc_a:" behaves exactly like writing "dlc_a")

## Save System (.gpsave)

- Slot saves: `saves/{title}_{identify_code}_SLOT{index}.gpsave`, where index is the slot number (save panel row 1 = 0-3, row 2 = 4-7; page 2 = 8-15, and so on).
- Quick save: `saves/{title}_{identify_code}_QSAVE.gpsave`, index is fixed at -1; it is not shown in the save panel and is always listed first when loading.
- A save file is a pickle-serialized list of 14 elements (index 0-13): title, identify code, thumbnail PNG, storyline config, current storyline, current page-1, speaker, words (multi-language dict), date, time, slot index, page-initial snapshot (bg/characters/chatbox/bgm), scores (branch score dict), package id of the save (":main:" for the main work, otherwise the DLC package id). Older saves missing indices 11-13 are handled with defaults (no snapshot -> rebuilt from the story, no scores, treated as main work).
- Settings file: `saves/{title}_{identify_code}_SETTINGS.gpsetting`, a pickle-serialized list of 8 elements: title, identify code, resolution ("fullscreen" when fullscreen), language, skip-read-text flag, BGM volume, voice volume, interrupt-voice-on-page-turn flag.
- Filename sanitizing: before being written into a filename, the title (window_title) and identify code (identify_code) both have spaces replaced with "-" and underscores "_" with "+" (e.g., "Sample story" -> "Sample-story"); the actual filename may therefore differ from the field text.
- Read history: `saves/{title}_{identify_code}_READED.gpreaded` (JSON, fully independent of saves; deleting saves does not reset read progress). On-disk structure: {"package|storyline:page": [read scene index, ...]}, with the reserved package id ":main:" for the main work. Skip/fast-forward stops automatically at unread content.

### Save panel / Load panel

The save panel and the load panel are the same panel component (SavePanel); the appearance is determined by `ui.bottom_menu.save` (save) or the additional config of `menu.menu_pos.load` on the main menu (load); the two config structures are the same.

- **Save panel** (click the bottom "Save" button during the story):
  - The panel shows 8 save slots (2 rows x 4 columns); each slot shows the thumbnail, line text, date and time; an empty slot shows the gray "SAVE" text.
  - Click an empty slot -> save directly to that slot; click a slot that has a save -> "Confirm overwrite?" appears; after confirming, the old save is deleted and the new one is saved.
  - A slot that has a save has a trash button at the bottom-right; clicking it shows "Confirm delete?"; click "Confirm" to delete that save, or click "Cancel" / click elsewhere to exit the confirmation.
- **Load panel** (click the "Load" button on the main menu):
  - The layout is the same as the save panel, except the title at the top-left is "Load Game" and the bottom toolbar has no "+" button; slots that have saves also have a trash button at the bottom-right, which can delete saves (the delete confirmation works the same as the save panel).
  - Click a slot that has a save -> "Confirm load?" appears; after confirming, the save is loaded and the story is entered (first fading into transition_color, then into the scene); an empty slot does nothing.
- **Paging**: the bottom toolbar of the panel has ◀ page-prev ▶ and the page number "current/total" on the left, and "Main Menu" and "Back" buttons on the right. Each page shows 8 slots; the page count is derived from the largest save slot index (index 8-15 is page 2, and so on); the "+" button can add a page (save panel only). Paging is circular: page 1 paging left goes to the last page, and the last page paging right returns to page 1.
- When a panel is opened, the bottom menu bar and the main-menu buttons are hidden and restored after closing; opening a panel pauses auto-play / skip.

### Bottom menu bar buttons

From right to left during the story (10 buttons in total):

1. **⊙ (hide)**: hides the dialogue box + bottom menu bar (including the bar itself) while the story keeps running; click anywhere to restore.
2. **Log**: opens the backlog panel (shows the lines that have been displayed in the current playthrough, translated according to the current language).
3. **Settings**: opens the settings panel (language switching, resolution switching, skip-read-text toggle, volumes; the settings are saved to the .gpsetting file).
4. **Skip-to-choice**: shows a confirm dialog "Jump to next choice?"; after confirming it fades to black, silently simulates the advance while the screen is black, and stays on that choice page (black duration = max(compute time + 500 ms, 1000 ms)); if the pre-check finds no target nothing happens.
5. **Skip (▷▷)**: auto-advances by simulating a click every 50 ms: if the text is not fully shown it is completed immediately; once the text is complete it moves on to the next scene/page (voice follows the "interrupt voice on page turn" setting). With "skip read text" enabled it stops automatically at unread content; disabled on the ending storyline (end); mutually exclusive with auto-play.
6. **Auto-play (▷)**: advances the story automatically.
7. **Load**: opens the load panel (same as the main menu "Load").
8. **Save**: opens the save panel.
9. **Q.Load (quick load)**: shows a confirm dialog, then loads the latest save (the quick save always sorts first).
10. **Q.Save (quick save)**: saves directly to the quick save slot (overwriting the old quick save).

Skip and Auto-play are mutually exclusive — enabling one automatically disables the other; opening a panel pauses both, and they resume after returning to the story.

### Hotkeys

- Space / Enter / left mouse button: advance the story (during typewriter display, clicking completes the display)
- A: auto-play toggle
- S: skip toggle
- Esc: closes the currently open backlog / settings / save / load panel (confirm dialogs can also be closed with Esc)
