This document is divided into 2 parts:
1. Explanation of Story JSON Rules
2. Example JSON Parsing

Note:
1. Unless otherwise specified, all file paths should be relative paths starting from the location of the JSON file.

This document is based on the actual content of the current story/sample_create.json and the code implementation, and replaces the old version of the rules.
Fields that are not implemented (such as edit_storylineID_value / check_storyline inside scenes) have been removed from the rules or marked as "reserved".



1. Explanation of Story JSON Rules:
Top-level keys: "settings", "ui", "menu", "story_and_position"

"settings": dictionary (optional; defaults are used when missing)
    Description: Used to configure language support, window size, title, etc. When missing or empty, the program uses defaults (language falls back to "zh", window 1280x720, title "GalPie").
    Keys inside "settings": "language", "window_size", "window_title", "identify_code", "transition_color"

    "language": dictionary (optional; defaults to "zh" when missing)
        Description: Sets the supported languages. The current format is a dictionary: {language tag: language display name}.
        The program takes the first language tag in the dictionary as the initial language. When missing or empty, the program uses "zh" as the current language.
        Explanation of keys inside "language": language tags, e.g., "zh", "en", "ja", "ru"
        Example: {"zh": "中文", "en": "English", "ja": "日本語", "ru": "Русский"}
        Legacy format is also supported: a list such as ["zh", "en", "ru"], the program takes the first element as the initial language.

    "window_size": string or list (optional)
        Description: Sets the window size. It can be a single resolution string (legacy format), or a list of resolution strings (new format; index=0 is the initial resolution).
        String format is "<width>x<height>", e.g., "1280x720".
        List format, e.g., ["1280x720", "1600x900", "1920x1080"]; the options in the list will appear in the resolution dropdown of the settings panel.
        If not provided, it defaults to "1280x720".

    "window_title": string (optional)
        Explanation of "window_title": Sets the title of the game window. If not provided, it defaults to "GalPie".

    "identify_code": string (optional)
        Explanation of "identify_code": Sets an identification code for this story, used to manage story save files more conveniently.

    "transition_color": list (optional; default [0, 0, 0] black)
        Explanation of "transition_color": Sets the color displayed in the window during transitions, RGB format, three integers from 0 to 255, e.g., [0, 0, 0].
        The program uses this color as the transition color block in the following transition scenarios:
        - After clicking "Start Game": the main menu fades out, first fading into this color, staying for about 1.5 seconds, then fading into the story.
        - After confirming a load from the main menu: likewise first fades into this color, then fades into the loaded scene.
        - When the scene is blank/cleared (no elements at all), the window background is also this color.

"ui": dictionary (optional; the default UI is used when missing)
    Description: Used to configure the interactive interface, such as the dialogue box and bottom menu. When missing, the default UI settings are used (default dialogue box style / name region / words region).
    Keys inside "ui": "chatbox_and_words_position", "bottom_menu"

    "chatbox_and_words_position": dictionary (optional; the default dialogue box style and regions are used when missing)
        Description: Settings of the dialogue box style. When missing, the default dialogue box style / name region [[76,60],[270,149]] / words region [[310,60],[805,149]] are used.
        All three keys inside it are optional, each using its default value when missing.
        Keys inside "chatbox_and_words_position": "chatbox", "name_show_region", "words_show_region"

        "chatbox": string (optional; the default dialogue box style is used when missing)
            Explanation of "chatbox": The storage location of the dialogue box style (should be an image). The path should be relative to the location of the JSON file, e.g., "./res/ui/chatbox.png"

        "name_show_region": list (optional; the default region [[76,60],[270,149]] is used when missing)
            Explanation of elements inside "name_show_region": The list should contain two lists, representing respectively the top-left and bottom-right coordinates of the region where the speaker's name is displayed inside the dialogue box. The coordinate system is based on the image of the dialogue box style "chatbox". The top-left corner of the image is the origin (0 point); the x axis increases to the right and the y axis increases downward. Format example: [[76,60],[270,149]], meaning the pixel at (76, 60) on the dialogue box style (image) is the top-left and the pixel at (270, 149) is the bottom-right of the region where the speaker's name is displayed.

        "words_show_region": list (optional; the default region [[310,60],[805,149]] is used when missing)
            Explanation of elements inside "words_show_region": Similar to "name_show_region"; the list should contain two lists, representing respectively the top-left and bottom-right coordinates of the region where the subtitle text is displayed inside the dialogue box. The coordinate system is based on the image of the dialogue box style "chatbox". The top-left corner of the image is the origin (0 point); the x axis increases to the right and the y axis increases downward. Format example: [[310,60],[805,149]], meaning the pixel at (310, 60) on the dialogue box style (image) is the top-left and the pixel at (805, 149) is the bottom-right of the region where the subtitle is displayed.

    "bottom_menu": dictionary (optional)
        Description: Sets the bottom menu bar during the story. If not provided, no bottom menu bar is shown.
        Keys inside "bottom_menu": "mode", "color", "button_color", "backlog_bgcolor", "save"

        "mode": string (optional)
            Explanation of "mode": The mode of the bottom menu; currently only "default" (preset style) is supported.
            default mode: Shows a semi-transparent menu bar at the bottom of the window, with the "Log" button, the "Settings" button, the "Skip (▷▷)" toggle, the "Auto-play (▷)" toggle, the "Save" button, and the "Quick Save (Q.Save)" button arranged from right to left.
            The Settings button opens the settings panel; the Log button opens the backlog panel; the Save button opens the save panel; the Quick Save button saves directly to the quick save slot (F2=save, F3=load latest save, A=auto-play, S=skip).
            Skip and Auto-play are mutually exclusive — enabling one automatically disables the other; opening the settings/log/save panel pauses both, and they resume after returning to the story.

        "color": list (optional)
            Explanation of "color": The fill color of the bottom menu bar, RGBA format, four integers from 0 to 255, e.g., [0, 0, 0, 200].
            Default value is [0, 0, 0, 255].


        "button_color": list (optional)
            Explanation of "button_color": The background color of the buttons on the bottom menu bar (Log/Settings/Skip/Auto-play/Save/Quick Save), RGBA format, e.g., [0, 0, 0, 200].
            Default value is [0, 0, 0, 255]. The button text color is chosen automatically based on the brightness of this color:
            - Sum of the three RGB values < 383: white text in normal state; on hover the button turns white with black text.
            - Sum of the three RGB values >= 383: black text in normal state; on hover the button turns black with white text.

        "backlog_bgcolor": list (optional)
            Explanation of "backlog_bgcolor": The background color of the backlog (log) panel, RGBA format, e.g., [255, 255, 255, 200].
            Default value is [255, 255, 255, 200].

        "save": dictionary (optional)
            Description: The interface configuration of the save panel / load panel. The save panel and the load panel share this structure (the load button on the main menu has its own config; see "menu_pos.load" below).
            Keys inside "save": "ui_mode", "color", "saves_color", "saves_text_color", "text_color", "button_color"

            "ui_mode": string (optional)
                Explanation of "ui_mode": The interface mode; currently only "default" (preset style) is supported.

            "color": list (optional; default [255, 255, 255, 217])
                Explanation of "color": The background color of the panel, RGBA format.

            "saves_color": list (optional; default [185, 122, 87, 255])
                Explanation of "saves_color": The background color of the save slots, RGBA format. On hover it automatically becomes lighter/darker while keeping the original hue: when the sum of the three RGB values < 383, it blends 35% toward white; when >= 383, it blends 35% toward black.

            "saves_text_color": list (optional; default [255, 255, 255])
                Explanation of "saves_text_color": The color of the text inside the save slots (line/date-time/trash icon/empty-slot "SAVE" text/confirmation text), RGB format.
                Note: the text of the confirm/cancel buttons is always white and is not affected by this config.

            "text_color": list (optional; default [30, 30, 30])
                Explanation of "text_color": The color of the static text inside the panel (the "Save Game"/"Load Game" title at the top-left, the page number at the bottom, etc.), RGB format.

            "button_color": list (optional; default [0, 0, 0, 255])
                Explanation of "button_color": The background color of the buttons on the bottom toolbar of the panel (◀ page prev ▶, + add page, Main Menu, Back), RGBA format. The text/hover rules are the same as the bottom menu bar's button_color (brightness < 383 white text/hover turns white with black text; >= 383 black text/hover turns black with white text).

"menu": dictionary (optional)
    Description: Sets the main menu (start screen). If not provided, the story starts directly on launch (playing from the first page of the current storyline) without showing a main menu.
    If provided, the main menu is shown first on launch, and the story starts only after clicking the "start" button.
    Keys inside "menu": "bg", "change", "title", "button", "button_touched", "text_rgb", "menu_pos"

    "bg": string (optional)
        Explanation of "bg": The path of the main menu background image (relative to the JSON file), e.g., "./res/menu/bg.png".

    "change": list (optional)
        Explanation of "change": The transition effect when the main menu appears. Format is [[r,g,b], "gradient"],
        i.e., a list consisting of a color and an effect name. The program takes the 2nd element (the effect name) as the transition effect.
        The 1st element (the color) is currently not used in the code and is reserved only.
        Currently supported effects: gradient "gradient".

    "title": dictionary (optional)
        Explanation of "title": The main menu title image, given by language tag with the image path.
        The program first takes the image for the current language; if absent, it falls back to the "zh" image; if still absent, it takes the first one.
        Example: {"zh": "./res/menu/title.png"}.

    "button": string (required)
        Explanation of "button": The path of the normal style image of the main menu button, e.g., "./res/menu/button.png".
        Note: The code directly indexes menu["button"]; if missing, an error is raised. Therefore, as long as "menu" is provided, "button" must also be provided.

    "button_touched": string (optional)
        Explanation of "button_touched": The path of the style image of the main menu button when hovered/pressed by the mouse, e.g., "./res/menu/button_touched.png".

    "text_rgb": list (optional)
        Explanation of "text_rgb": The color of the main menu button text, RGB format, three integers from 0 to 255, e.g., [255, 255, 255].
        Default value is [255, 255, 255].

    "menu_pos": dictionary (optional)
        Description: Sets the positions and texts of the title and buttons in the main menu.
        Explanation of keys inside "menu_pos": It can contain "title" and any button tags (such as "start", "load", "settings", "quit").

        "title": list (optional)
            Explanation of elements inside "title": The position coordinate [x, y] of the title image on the main menu background.
            The coordinate system is based on the main menu background image. The top-left corner of the image is the origin (0 point); the x axis increases to the right and the y axis increases downward.
            Example: [54, 48].

        <button tag>: list (required, e.g., "start"/"load"/"settings"/"quit")
            Description: Sets a main menu button. The list structure is: [position, text dictionary, additional config (optional)]
            1st element: The position coordinate [x, y] of the button image on the main menu background.
            2nd element: The text dictionary, giving the button text by language tag, e.g., {"zh": "开始游戏", "en": "Start Game", "ja": "ゲーム開始", "ru": "Начать игру"}.
                The program takes the text for the current language; if absent, it takes the first text in the dictionary.
            3rd element (optional): The additional config dictionary, e.g., {"ui_mode": "default"}.
            Currently built-in supported button tags and their functions:
                "start": Start the game; clicking enters the story.
                "load": Opens the load panel (load game interface). Its additional config dictionary has the same structure as the "save" config of the bottom menu bar (color/saves_color/saves_text_color/text_color/button_color), used to set the appearance of the load panel; defaults are used if not provided.
                "settings": Opens the settings panel (language/resolution switching, etc.). Its additional config dictionary (ui_mode/color/text_color/button_color) is used to set the appearance of the settings panel; defaults are used if not provided.
                "quit": Quit the game.
            Other custom button tags are currently not bound to any function (clicking does nothing); they are displayed only.

"story_and_position": dictionary (required)
    Description: Sets the story content, characters, backgrounds, etc.
    Keys inside "story_and_position": "character_and_motion", "backgrounds", "storyline_id", "story"

    "character_and_motion": dictionary (optional; referencing a character in a scene prints "character not defined" when missing)
        Description: Sets the characters that have sprites
        Explanation of keys inside "character_and_motion": Custom character tags, e.g., "girl", "congyu", "丛雨"

        <character tag>: dictionary (required)
            Keys inside a character tag: "name", "form", "face"

            "name": dictionary (required)
                Description: Sets the title/address of this character tag in the game
                Explanation of keys inside "name": The language tags defined in "language" of "settings", e.g., if {"zh": "中文", "en": "English"} is set in "language", this dictionary should be: {"zh": "丛雨", "en": "Murasame"}

                <language tag>: string (required)
                    Content explanation: Sets the title/address of this character tag in different languages in the game

            "form": dictionary (required)
                Description: Sets the different forms of this character, and sets the image file path each form points to
                Explanation of keys inside "form": Custom form tags, e.g., "校服", "工作", "校服2"

                <form tag>: string (required)
                    Content explanation: The image file path the form points to, e.g., "校服": "./res/character/girl/uniform.png"

            "face": dictionary (optional)
                Description: Sets the facial expressions of this character, and sets the image file path each expression points to. You may also include the expression directly in the form image and call that form directly in the story later, thus omitting this part.
                Explanation of keys inside "face": Custom expression tags, e.g., "微笑", "脸红", "平常"

                <expression tag>: string (required)
                    Content explanation: The image file path the expression points to, e.g., "脸红": "./res/character/girl/shy.png"

    "backgrounds": dictionary (optional; referencing a background in a scene prints "background not defined" when missing)
        Description: Sets the tags of different backgrounds, and sets the image file path each background points to
        Explanation of keys inside "backgrounds": Custom background tags, e.g., "学校", "教室", "公园"

        <background tag>: string (required)
            Content explanation: The image file path the background points to, e.g., "公园": "./res/bg/park.png"

    "storyline_id": dictionary (optional; defaults to entering the "main" storyline when missing)
        Description: Sets the tags of the storylines
        Explanation of keys inside "storyline_id": Custom storyline tags

        <storyline tag>: float (required)
            Content explanation: The magnitude of the value decides which storyline is opened. When the story starts, the program compares the values of the tags and automatically enters the storyline with the largest value.
            For example, if {"main": 1.0, "girl": 0.5} is set here, the story will start by entering the storyline tagged "main".
            Note: Try to avoid two tags having equal values when they are both the largest among all tags. If this situation exists, the program enters the storyline of the first such tag that appears.
            (Note: The scene-level storyline value adjustment feature edit_storylineID_value / check_storyline from the old document is not yet implemented in the code; it is reserved only.)

    "story": dictionary (optional, but a storyline tag must correspond to a key here, otherwise that storyline has no content)
        Description: The story content of each storyline. If missing, or a storyline tag has no corresponding content, "story over" is printed when playing.
        Explanation of keys inside "story": The storyline tags set in "storyline_id" above

        <storyline tag>: dictionary (required)
            Description: Story and plot content, as well as the settings of scenes and subtitles. Note that with "clear_all": false, the scene settings of the previous page continue to exist if not set again; if some part is set again, that part is replaced with the new settings (where "bg" is replaced as a whole, and "characters" is replaced tag by tag: the character tags that are set again are replaced with the new settings, while other characters that are not set are kept). You can learn more in the example JSON parsing in Part 2.
            Explanation of keys inside the dictionary: page number, starting from 1

            <page number>: list (required)
                Description: Sets the scenes of this page
                Explanation of elements inside the list: The elements are dictionaries; if the list has n elements (dictionaries), it means there are n scenes (n cannot be less than 1)

                Element inside the list: dictionary (required)
                    Description: The settings of a scene
                    Keys inside the dictionary: "clear_all", "change", "bg", "characters", "chatbox", "content"

                    "clear_all": bool (optional, default false; but the "clear_all" of the first page of every storyline must be true)
                        Description: Whether to clear the content of the previous page's scenes. true means yes, false means no. The "clear_all" of the first page of every storyline must be true, otherwise the content of the previous storyline/page will remain.

                    "change": string (optional)
                        Explanation of "change": Sets the transition effect; by default it changes directly
                        Currently supported effects:
                            Gradient  "gradient"

                    "bg": string (optional)
                        Explanation of "bg": Sets the background; the content should be a background tag set in "backgrounds" above, e.g., "bg": "公园"

                    "characters": dictionary (optional)
                        Description: Sets the characters with sprites to appear on stage
                        Explanation of keys inside "characters": The character tags set in "character_and_motion" above

                        <character tag>: dictionary (required)
                            Description: Sets the form, position, expression, zoom, animation, etc. of the character appearing on stage
                            Keys inside the dictionary: "form", "pos", "face", "zoom", "animate"

                            "form": string (required)
                                Explanation of "form": The form tag set in "form" of this character tag in "character_and_motion" above

                            "pos": list (required)
                                Explanation of elements inside "pos": The list should contain two values, corresponding to the x and y coordinates of the form image on the background image. The coordinate system is based on the background image. The top-left corner of the image is the origin (0 point); the x axis increases to the right and the y axis increases downward. Format example: [320,80], meaning the form image is placed at the pixel (320, 80) on the background image.

                            "face": list or string (required)
                                Explanation of "face": There are two ways to write it.
                                List form: It has two elements. The first is a string, the expression tag set in "face" of this character tag in "character_and_motion" above; the second is a list containing two values, corresponding to the x and y coordinates of the expression image on the form image. The coordinate system is based on the form image. The top-left corner of the image is the origin (0 point); the x axis increases to the right and the y axis increases downward. Format example: [0,0], meaning the expression image is placed at the pixel (0, 0) on the form image. The whole list format is: ["脸红",[0,0]].
                                Note: In the code, setup_character only takes the 1st element of the list (the expression tag); the 2nd element (the offset coordinate) is not used in the current version. The expression is always drawn at the top-left corner (0,0) of the form image; this coordinate field is reserved.
                                String form: Fill in the expression tag directly, e.g., "face": "平常".
                                Note: The code directly indexes char_info["face"]; if missing, an error is raised. Therefore, as long as "characters" is provided, "face" must also be provided.

                            "zoom": float (optional)
                                Explanation of the value of "zoom": Sets the zoom of the character, default 1.0. Less than (<) 1.0 shrinks, greater than (>) 1.0 enlarges.

                            "animate": list (optional)
                                Description: Sets the animation of the character in this scene
                                Explanation of elements inside the list: The elements are lists; each list is a group of animations. Animations within the same group play simultaneously, and groups play in sequence.

                                Element inside the list (a group of animations): list (required)
                                    Elements inside the group: dictionaries; a group can contain multiple animations, which play simultaneously.

                                    Keys inside the dictionary: "time", "zoom", "move"

                                    "time": float (optional; if missing or 0, that animation is skipped; it is recommended to fill it in)
                                        Explanation of the value of "time": The duration of the animation, in seconds. If missing or 0, the animation is not executed (skipped directly).

                                    "zoom": float (optional)
                                        Explanation of the value of "zoom": Sets the zoom animation. Within the animation duration ("time"), the character's zoom changes from the value of "zoom" above to this value. If it is not the first group, it zooms from the value at the end of the previous group to this value. You can learn more in the example JSON parsing in Part 2.

                                    "move": list (optional)
                                        Explanation of elements inside "move": The elements are lists with no specific upper limit on the number of elements; each list contains two numbers, corresponding to the x and y coordinates. The x axis increases to the right and the y axis increases downward. The coordinates are relative to the character itself. Within the animation duration ("time"), the character moves to the relative coordinates in order. Example: to move the character left 10, then down 10, then right 10, then up 10, fill in: [[-10,0],[0,10],[10,0],[0,-10]]

                    "chatbox": dictionary (optional)
                        Description: Controls the showing and hiding of the dialogue box (and the name/subtitle display regions)
                        Keys inside "chatbox": "visible", "change"

                        "visible": bool (required)
                            Explanation of the value of "visible": Whether to show the dialogue box. true shows it, false hides it.

                        "change": string (optional)
                            Explanation of "change": The transition effect of showing/hiding the dialogue box. Currently supported effects:
                                Gradient  "gradient"

                    "content": dictionary (optional)
                        Description: Sets the dialogue content. Scenes without this field (such as pure background-switching pages) are directly marked as having text and audio finished, and automatically advance to the next scene / wait for page turning.
                        Keys inside "content": "speaking"/"speaking_name", "words"

                        "words": dictionary (required; as long as "content" is written, "words" must be present)
                            Description: Sets the dialogue subtitle for the language corresponding to each language tag. You can learn more in the example JSON parsing in Part 2.
                            Note: In the code, display_dialog directly indexes content["words"]; if missing, an error is raised. Therefore, as long as "content" is written, "words" must be provided.
                            The subtitle takes the text for the current language; if absent, it falls back to "zh"; if still absent, an empty string.
                            Explanation of keys inside "words": The language tags set in "language" of "settings" above

                            <language tag>: string (required)
                                Content explanation: The subtitle of the dialogue in the language corresponding to this language tag

                        "speaking": dictionary / "speaking_name": string (both optional; both may be omitted; if both are omitted, the name is displayed as empty)
                            Description: Sets the speaker's name. If both are filled in, "speaking_name" takes priority.
                            Explanation of "speaking": Sets the speaker's name for the language corresponding to each language tag. You can learn more in the example JSON parsing in Part 2.
                            The name takes the text for the current language; if absent, it falls back to "zh"; if still absent, an empty string.
                            Explanation of keys inside "speaking": The language tags set in "language" of "settings" above

                            <language tag>: string (optional)
                                Content explanation: The speaker's name in the language corresponding to this language tag (can be an empty string "", meaning no name)

                            Explanation of "speaking_name": If the speaker is set in "character_and_motion" above, the character tag set there can be used directly here
                            Content explanation of "speaking_name": The character tag set in "character_and_motion" above. The program takes the title for the current language from the "name" dictionary of that character; if absent, it falls back to "zh"; if still absent, an empty string.

## Save System (.gpsave)

- Slot saves: `saves/{title}_{identify_code}_SLOT{index}.gpsave`, where index is the slot number (save panel row 1 = 0-3, row 2 = 4-7; with future paging, page 2 = 8-15, and so on).
- Quick save: `saves/{title}_{identify_code}_QSAVE.gpsave`, index is fixed at -1; it is not shown in the save panel and is always listed first when loading (F3).
- A save file is a pickle-serialized list of 11 elements: title, identify code, thumbnail PNG, storyline config, current storyline, current page-1, speaker, words (multi-language dict), date, time, slot index.
- Save panel: clicking an empty slot saves to that slot; clicking a slot that has a save asks "Confirm overwrite?" (after confirming, the old save is deleted and the new one is saved); the trash button asks "Confirm delete?".
- Load panel: clicking a slot that has a save asks "Confirm load?"; after confirming, the game fades into the transition color and then enters the loaded scene. The load panel has no "+ add page" button on the bottom toolbar; the trash (delete) icons ARE shown in the load panel too, and deleting a save uses the same confirmation as the save panel.
- Paging: each page shows 8 slots; the toolbar at the bottom-left has ◀ page-prev, the page number (current/total), ▶ page-next (right-paging is circular: on an empty page it returns to page 1, on page 1 paging left goes to the last page), and "+" (only in the save panel) adds a page; the total page count is derived from the largest existing slot index (max_index // 8 + 1, at least 1). The bottom-right has "Main Menu" and "Back" buttons.
- When a panel is opened, the bottom menu bar and the main-menu buttons are hidden, and auto-play / skip are paused; they resume after returning to the story.
- Bottom menu bar buttons, from right to left: Log, Settings, Skip (▷▷), Auto-play (▷), Save, Quick Save (Q.Save).
- Hotkeys: Space / Enter / left mouse button = advance (during typewriter display, clicking completes the display); A = auto-play; S = skip; F2 = save (normal save to slot 0); F3 = load latest save (quick save first); Esc = close the currently open panel.
- Settings file: `saves/{title}_{identify_code}_SETTINGS.gpsetting` (contents: title, identify code, resolution, language).
